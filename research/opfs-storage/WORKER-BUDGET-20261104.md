# Verified content worker budget

The OPFS VerifiedContent adapter admits one heavy worker at a time across cooperating tabs and accounts on an origin using the exclusive `codi-file-heavy-worker/1` Web Lock. Capture, legacy verification, OPFS verification and independent read-copy use the same queue. Queued callers retain their existing Blob references without normalizing/copying them before admission; this is not a bound on memory already held by apps. A queued request can be cancelled by its signal or closing the adapter, and waits at most 180 seconds by default before a `StorageUnavailable` worker-queue-timeout. A worker keeps its own existing execution deadline. The global slot covers work, not the lifetime of returned snapshot leases. Web Locks release on renderer/page death. Cooperating same-origin code must use this adapter: other code, gateway SDK workers, browser allocations, and other origins are not bounded by this lock.

Real Chromium with two tabs and separate account scopes: four simultaneous 4 MiB captures followed by four verified lease reads retained correct bytes, with a maximum of one instrumented OPFS worker. The capture-plus-verification run took roughly 1.8–2.2 s locally. A 20 ms foreground timer had a longest observed gap of about 20–25 ms in these runs; the background tab was throttled to approximately one second. This is not a 100-user, 128 MiB, mobile, network throughput, total RAM, or responsiveness guarantee. Serialization can increase waiting time and the 180-second admission deadline may require users to retry under load.

The test held a worker while verifying FIFO admission across tabs, cancelled another account's queued capture and a queued legacy verification, exercised a shortened queue timeout, a hung-worker timeout and a failed worker, and verified that the next job proceeded. `Page.crash` terminated the holding renderer while another tab waited; the next job proceeded. Existing OPFS cancellation and generation-lease tests passed. A real signed c046/44da partial-download and retry test also passed with this gate. The renderer-crash test is not a browser-wide power failure or adversarial same-origin code test.

Run `tests/files-worker-budget.test.cjs` against this checkout served on `http://127.0.0.1:19993/`, with a disposable Chromium CDP endpoint at `http://127.0.0.1:19294/`, `NODE_PATH` pointing to puppeteer-core, and `CODI_TEST_RENDERER_CRASH=1` to exercise renderer crash. Both addresses can be overridden through `CODI_TEST_URL` and `CODI_TEST_CDP`.

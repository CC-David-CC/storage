# 128 MiB signed changed-chunk test with worker admission

On R730, source 544480232 with the one-origin VerifiedContent worker gate, isolated c046 gateway and exact 44da SDK ran one complete 128 MiB random file save and sync, followed by a one-byte edit and sync. Server version and independently verified local snapshot reported the same final hash and 134,217,728-byte size. Instrumented application request bodies during the edit and sync totaled 71,470 bytes, excluding HTTP/TLS overhead and response bytes. The initial write and sync took 57.944 seconds. A second tab with a distinct test storage scope queued an operation while the first worker was deliberately paused just before dispatch; closing that second adapter cancelled it without starting a worker. Maximum instrumented VerifiedContent workers was one.

Sampled peak sum of Chrome process RSS was 1,419,755,520 bytes over 425 samples; shared pages are counted more than once, and this includes SDK/Blob/browser allocations, not just OPFS workers. A 20 ms foreground timer's largest observed gap was 32.185 ms over 5,242 samples. These figures describe one local run, not a total-memory cap, a mobile/100-user claim or real WAN performance. The second scope was not a separately signed-in account; this run proves queue cancellation across scopes, not account authorization. Existing independent account tests cover the latter separately.

The first attempted run timed out because its harness polled for a transient lock after placing the primary tab in the background. It did not qualify as a pass. The corrected harness holds the first real worker before dispatch until the other tab is queued and cancelled, then resumes it. No product change or live service was involved.

The isolated fixture checks the c046 and 44da hashes. With Python dependencies and verified artifact paths described by `worker-budget-large-fixture.py`, start it on loopback 19989, then run `CHROME=/path/to/chrome node tests/mirror-opfs-worker-budget-large.test.mjs` with puppeteer-core installed. The test uses `/mnt/data10tb` for its disposable Chromium profile and stops the browser if sampled summed RSS exceeds 3 GiB. The final test additionally asserts edit request bodies are below 1 MiB; the observed 71,470 bytes satisfies that bound.
